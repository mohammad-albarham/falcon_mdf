What changed

  • Correctness: Signal::mean() now propagates a decoding error. Previously, a truncated second sample after a value of 6 produced an average of 3. The regression failed on the old implementation and passes after the fix.
  • Compression: switched flate2 from miniz_oxide to its Rust zlib-rs backend and decoded borrowed input directly, avoiding an unnecessary input buffer. Locked versions: flate2 1.1.5, libz-rs-sys and zlib-rs 0.5.5.
  • Transposition: reconstructs DZ data in 16 KiB bands of output rows, keeping destination cache lines in use. Record ordering and untransposed tail bytes are preserved.
  • Numeric decoding: reads standard 1/2/4/8-byte widths directly. Nonstandard widths retain byte assembly; bit masking and sign conversion remain intact.
  • Tests: removed repeated timing loops from two integration tests and replaced them with value, type, validity and metadata assertions. Consolidated transpose-oracle Python calls, removed unused fixture parameters and added tail, empty-buffer and cache-boundary cases.
  • Instructions: shortened AGENTS.md, removed provider restrictions and stale workspace detail, and retained verification, format correctness and benchmark requirements.

Scope and reproducibility

This review focused on core numeric decoding, DZ decompression/transposition, aggregate error handling and related tests. It is not an exhaustive audit of every export, bus decoder, GUI or Python binding. Large fixtures are repeated J1939 data written by asammdf, and do not represent the structural variety of arbitrary vendor recordings. All performance measurements use warm OS caches on this machine.

The compression backend contains upstream unsafe Rust internally; no unsafe code was added to the reader. It does not require a C compiler. See flate2's backend documentation.
